# Action02b：SQLite逐例台账最小实现

本步骤把配置固定、单条请求、每次尝试、模型回答和执行错误写入SQLite。Python标准库SQLite事务用于原子更新；没有引入新的依赖，也没有启动真实模型或下载音频。

## 行为约定

- 一个数据库运行对应一个不可变的 `run_id` 与完整配置JSON。相同run_id配置变化会拒绝打开，改配置需另建运行。
- 请求键由运行配置指纹、源ID、音频SHA-256、任务、条件和重复编号生成；同一请求重复登记会返回原键，不重复排队。
- 每次执行新增attempt记录。失败和重试留痕；成功回答与completed状态在同一SQLite事务提交。
- 空字符串代表模型成功返回空回答，仍记为completed；加载、超时或进程退出不能伪装为空回答。
- 重开后显式调用 `recover_interrupted()`，它只将已提交的running尝试改为interrupted，保留此前completed及失败记录。调用方负责确保没有并发运行中的写入者。
- `backup_to()` 使用SQLite backup API，目标必须不存在，完成后执行 `PRAGMA integrity_check`；这不是异盘备份，也不保证抵御磁盘损坏或物理断电。

## 验证

新增测试覆盖配置变化拒绝复用、空答案、失败后保留重试历史、子进程直接退出后恢复未完成条目，以及备份完整性。中断测试模拟进程非正常退出，不等价于物理断电测试。

命令：`python -m unittest discover -s tests -p test_run_store.py -v`。本提交通过PR触发CI后再记录远端结果；当前执行环境的工作区为只读，因此没有本地运行结果。真实模型、数据许可清单与音频缓存下载校验仍未接通；不得据此启动长时间推理。
