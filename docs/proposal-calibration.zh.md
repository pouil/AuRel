## 1. 结论

存在方向偏差：仓库以合成音调、搜索、博弈演示为主，真实数据工作集中于情绪配对；当前应以“公开数据＋现成模型＋声学扰动＋标准性能比较”为主。继续扩展旧情绪32对、自适应攻击或自动缩减，会挤占主实验进度。

校准后的逻辑：固定公开语音及正确答案 → 运行原始输入 → 分别施加固定强度的扰动 → 对相同样本运行相同模型 → 比较绝对性能及变化 → 分析错误、可懂度和失败率。蜕变关系组织成对输入，不代替正确答案。没有性能下降也是有效发现。

不训练、不付费、不扩展安全攻击研究。旧代码与数据保留。11月4日受限停止报告作为历史记录；本次按新请求恢复校准工作，没有重启每日自动任务。

## 5. 模型、数据与扰动建议

转写建议LibriSpeech dev-clean用于试点，之后固定test-clean子集用于最终评估；官方许可CC BY 4.0。意图候选MINDS-14单一英语子集，如en-US，数据卡CC BY 4.0，含转写及14类意图。它只有train split，需明确自定开发/评估划分，不能冒充官方测试集；不要将非英语音频的英文翻译用于逐字转写评分。两个任务可以用不同数据，分别解释。

先用小型Whisper配置跑通转写，再试一个音频指令模型。Qwen2-Audio-7B是候选，现有8GB显存不能保证运行；先核验内存、CPU或量化可行性，再决定配置。专用ASR与通用模型只比较共同任务，不强行为ASR填写意图指标。最终checkpoint、revision、prompt和解码参数尚未确定。

proposal候选强度：噪声SNR 30/20/10 dB；混响RT60 0.2/0.4/0.6秒（需能测量或可靠标定）；压缩64/32/16 kbit/s；衰减−6/−12/−18 dB；保音高语速1.1/1.2/1.3倍。均需试点，尚未证明标签保持。噪声与房间响应须有明确许可；记录实际SNR、裁剪、峰值、时长、编码器版本。模型自动归一化可能抵消音量变化，必须记录；直接改采样率不能充当保音高语速变化。

最小闭环：一个任务、一个模型、固定小子集、干净＋一种轻扰动，先得到可重复指标和逐例记录。之后扩到五类、多强度和第二模型。proposal中的2系统×2任务×100条×16条件=6400次是后续预算示例，不是立即执行承诺。

## 6. 怎样使用本次新增评分

```bash
python -m pip install -e ".[evaluation]"
python -m unittest discover -s tests -v
python -m aurel.score_asr --input examples/asr-scoring-fixture.jsonl --output runs/scoring-check.json
```

示例是人为测试文本，绝非模型输出。输入每行一个源：source_id唯一编号、reference正确转写、clean原音频回答、perturbed扰动音频回答。一份文件仅一个模型和一个扰动条件。预期4个参考词、2个删除错误，干净WER=0、扰动WER=0.5、增量=0.5。不能平均每句WER。CER是字符错误率辅助指标；负增量代表改善，不截为零。

当前归一化只统一空白，保留大小写和标点。正式实验前固定归一化政策并版本化。空回答按错误计；网络/加载失败不能填成空回答。本入口只接受两侧完成的配对，还没有全部尝试数、传输失败统计、意图评分或置信区间，因此不是完整评估框架。正式报告还需全部尝试/完成/评分数、共同完成子集和逐例记录，避免选择偏差。置信区间按源句或说话人分组，不能把其多个变体当独立样本。
