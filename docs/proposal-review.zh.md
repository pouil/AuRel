# AuRel proposal 评审与实施路线

## 1. 应保留的贡献

同一音频对配两种任务，是最重要的实验单位。MR-I 检查无关声学变化下的不变性，MR-E 检查相关变化下的等变性，MR-C 检查加入干扰后前两者是否仍成立。覆盖生成 → 违规引导搜索 → 有效性与 oracle 审核 → 最小反例，是软件测试方法的贡献链。

保留“违规候选不等于确认漏洞”的区分。不要仅按输出变了就记失败：两个输出可以不同但都正确，也可以相同但都错误。除了关系通过率，还要报告绝对正确率与 clean-correct 条件下失效率。

## 2. 将最新的安全红队意图纳入主线

原稿将 safety 留到扩展；当前意图明确要求安全实验。建议采用共同测试引擎下的两条实验轨道：

- 诊断轨：词义事实抽取 + 副语言辨识，确认任务条件化关系确实有效。
- 安全轨：保持请求词义和安全政策标签不变，改变情绪/紧迫感/噪声，测试安全判断是否不合理翻转。同时配置良性请求，测量过度拒绝。

情绪识别变化是 MR-E；相同请求的语气变化通常不应改变政策允许与否，是 MR-I。但语气可能合理影响共情表达或紧急响应方式，所以安全 oracle 应检查具体政策行为，不能要求整段回复逐字相同。不要把“听起来焦急”作为现实危险事实的唯一标签。

第一版只选择一种预先定义的策略规则和小规模有标注请求集，在自有/授权模型上测试。测试录音与真实人的声纹身份解绑。研究贡献表述为“任务条件化、安全策略相关的声学交互失效发现”，不要在尚未验证前宣称新攻击或内部机制。

## 3. 博弈论应如何进入

固定模型、固定防御，仅选择扰动算子：这是黑盒优化/多臂老虎机。UCB 是合适基线，但不是博弈论贡献。

真正的两方设置：攻击者选择变换族、强度、组合与顺序；防御者选择预先定义的输入处理或提示策略。先固定有限策略集合，建立损失矩阵 L(a,d)，求 min_q max_p p^T L q。p 和 q 分别是攻击/防御混合策略。

攻击输入必须满足有效性硬约束 V(x,T)=1；无效音频不能靠增加惩罚项后仍被算作成功。防御同时满足良性效用下降 ≤ ε 和延迟 ≤ τ，防止“全部拒绝”或“删除所有副语言信息”的退化最优解。若纳入成本和多个效用，这通常不再是简单零和博弈，应明确建模或作为受约束优化。

只有在防御先承诺、攻击观察并响应的协议下才使用 Stackelberg 表述。普通静态模型比较不能称为均衡求解。均衡也只针对有限策略空间；报告 best-response gap，不宣称全局鲁棒。

推荐顺序：随机搜索 → 单因素/固定网格 → pairwise 覆盖 → UCB/上下文 bandit → 有限策略博弈。若博弈策略在相同预算和最终留出数据上没有增益，应如实报告，不为标题硬加博弈论。

## 4. 形式化与判定修正

令 y=π_q(M(a,q)) 为按任务抽取的结构化输出，R_q(y,y') 为预先规定的关系。MR-I 可要求槽值相等；MR-E 应指定标签映射或允许的关系集合。情绪常有歧义，不能仅用 TTS 风格标签当 g_q 真值。

A(l,p,n) 是控制实验的抽象，不代表真实波形能被独立解耦。变速、音量、重音和情绪可能彼此影响，所有算子都要有适用任务和排除条件。

严格交互反例需要同一 source/task 下四格：clean、T_p、T_n、T_n∘T_p。前三格通过相应关系、组合格失败，且四格有效，才能记为 interaction-only failure。还需检查 T_p∘T_n，因为顺序可能不同。随机生成模型需要重复采样，避免单次输出波动制造交互。

缩减采用有效性保持的局部 1-minimal 定义：每删除一个剩余因素都不再保持有效失败。不能承诺全局最小。强度失效常不单调，不能无条件二分；提示词缩减必须保持任务意图。

## 5. 可检验 RQ 和指标

| RQ | 实验与主要指标 |
|---|---|
| RQ1 任务条件化依赖哪里失效？ | 分任务 MR-I/MR-E/MR-C 违规率、绝对正确率、配对任务联合通过率 |
| RQ2 搜索是否有效？ | 等预算下独立有效反例数量、每千次查询发现量、time-to-first、有效输入比例 |
| RQ3 安全失效是否可适应防御？ | clean-safe 条件下策略违规率、良性过拒率、效用/延迟、留出攻击下最坏风险 |
| RQ4 诊断是否可信？ | 人工确认精度、重现率、缩减比例、交互专属失败比例及消融 |

安全指标：新增策略违规率 = clean 遵守策略且 transformed 违规的有效配对数 / clean 遵守策略的有效配对数；同时报告分母、无效样本数、总违规率与良性误拒率。判断违规依据输出内容，而非未拒绝、某个关键词或模型自评。

统计单位是 source group，不是全部变体。按说话人及脚本隔离训练/选择/最终测试，报告配对或分组 bootstrap 置信区间、多随机种子和去重规则。搜索集与报告集分开；人工复核失败及随机通过样本，避免只审核“成功攻击”。

所有调用均计费计数，包括 clean、重试、judge 和缩减。先用少量实测每调用成本乘计划调用数，不在未授权前批量调用付费服务。

## 6. 技术栈建议

| 层 | 选择 | 理由与约束 |
|---|---|---|
| 运行环境 | Python 3.11 + 独立环境 | 第一版避免复杂服务化；验证后冻结依赖版本 |
| 核心音频 | NumPy、SciPy、soundfile、librosa、FFmpeg | 显式记录采样率、增益、SNR、codec 和处理顺序 |
| 模型 | PyTorch + Transformers；先 Qwen2-Audio-7B-Instruct | 官方提供音频+文本输入示例；先适配一个模型再横向扩展 |
| 数据与配置 | JSONL manifest、dataclass/Pydantic、YAML | audio hash、source/speaker/script ID、变换参数、许可、标签、验证记录 |
| 搜索 | random、覆盖数组、自实现 UCB；后续 Optuna | 共享预算、seed、去重和有效性门控 |
| 博弈 | NumPy 原型；正式可用 SciPy 线性规划 | 明确有限矩阵与上下界；先做基线 |
| 追踪 | JSONL + SQLite 可选，之后 MLflow | 可重放与缓存优先；不需前期部署仪表盘 |
| 验证 | unittest/pytest + GitHub Actions | 测预算、标签关系、变换有效性、组隔离和缩减不变量 |

候选列表应写精确模型 ID、revision、音频输入支持与访问方式，不能只写 Claude/Llama/Mistral/Qwen 家族名称。输入音频输出文本的模型不必是 speech-to-speech；不要用“端到端必定无中间文本”作为架构分类依据。对其他候选的当前音频支持逐一核查后再纳入。

## 7. 分阶段验收

1. 方法试验：选一种副语言因素、一个事实槽任务、一个副语言任务、两种 nuisance；先做人工校验的真实语音配对。合成音调只验证程序。
2. 真实模型 MVP：一个精确版本模型、音频读取/重采样适配器、固定关系 oracle、每例缓存和预算账本；验收可重放同一结果。
3. 交互发现：覆盖数组、四格诊断、有效性保持缩减；与 random/单因素同预算比较。
4. 安全实验：独立标签规则、良性对照、人工校准 oracle；验证发现的行为具有安全意义。
5. 博弈实验：固定策略集并测矩阵，训练集选择策略，最终留出集评估；报告效用约束与 gap。

第一版不加入训练、声纹身份、音乐、音频生成质量或多语言扩展。本机已检测到 NVIDIA GeForce RTX 4060 Laptop GPU，8188 MiB 显存，驱动 555.97；当前环境是 torch 2.14.0+cpu，CUDA 不可用。可承担音频处理和调度；7B 模型 FP16 权重约 14GB（十进制），尚不含激活和运行开销，不能假设 8GB 显存可直接容纳。后续在独立环境验证兼容的 CUDA PyTorch 与量化/offload 方案，或者使用远端 GPU。量化配置本身须作为实验条件记录，不能把量化版与全精度版视为同一处理条件。

## 8. 相关研究定位（已核查来源）

- [DEAF](https://arxiv.org/abs/2603.18048)：词义/提示与声学冲突下的忠实性诊断。AuRel 需要额外证明双任务关系与自动交互搜索的价值。
- [AudioTrust](https://proceedings.iclr.cc/paper_files/paper/2026/hash/2aa212d6f40c1cb19b777e83db00ec6a-Abstract-Conference.html)：广泛的音频可信性评测，涉及非语义声学线索。不能仅以“声学影响安全性”作为创新。
- [Qwen2-Audio 官方仓库](https://github.com/QwenLM/Qwen2-Audio)：首个模型适配器的实现依据。

本轮是研究定位与可运行骨架，不是全面文献复现，也未完成 novelty 的系统性证明。
