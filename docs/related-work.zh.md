# 已有成果能帮我们什么

核查日期：2026-10-21。下表区分作者已有成果、我们能借鉴的部分和仍需自己证明的部分。查阅范围为论文摘要、作者项目页和仓库说明，不代表已经复现实验，也不是穷尽所有文献的 novelty 审核。

| 成果与来源 | 已有工作 | 对 AuRel 的具体用途 | 不能直接替我们证明什么 |
|---|---|---|---|
| [LISTEN，EACL 2026](https://aclanthology.org/2026.eacl-long.274/)；[作者项目页](https://delijingyic.github.io/LISTEN/index.html) | 研究情绪理解中词义与声音线索的依赖，报告所测模型的词义主导现象 | 借鉴对齐/冲突和模态对照；构造只改变声学线索的检查 | 单纯展示情绪冲突并不是我们的新贡献 |
| [DEAF](https://arxiv.org/abs/2603.18048) | 通过情绪、背景声、说话人等冲突刺激诊断声学忠实性 | 借鉴声学证据与文字提示的分离方法 | 任务成对关系、自动组合搜索与缩减需要额外实验 |
| [AudioTrust，作者仓库](https://github.com/JusperLee/AudioTrust)；[论文](https://arxiv.org/abs/2505.16211) | 涵盖安全、鲁棒性、隐私等维度，并提供推理/判分框架 | 后续安全轨参考数据字段、模型适配与判分结构 | 情绪判断错不等于安全违规；其 judge 也不能免校准复制 |
| [AudioBench，作者仓库](https://github.com/AudioLLMs/AudioBench) | 统一多个音频任务、数据集和评测接口 | 参考模型与数据拆分、运行组织方式；减少重复造基础设施 | 广泛能力得分不等于任务条件化依赖 |
| [MTAM：Metamorphic Testing for Audio Content Moderation Software](https://arxiv.org/abs/2509.24215) | 用蜕变关系测试音频内容审核中的错误 | 安全+蜕变测试方向必须比较的近邻工作 | 不能以“对音频做扰动并找错误”作为唯一创新；审核分类与生成模型策略也不同 |
| [CREMA-D，官方数据仓库](https://github.com/CheyneyComputerScience/CREMA-D) | 多位演员朗读有限台词、多情绪版本，附人工感知结果 | 本轮用同说话人/同台词配对，优先 audio-only 标签 | 表演型、有限台词不代表现实语音；有标注也仍可能不清晰 |
| [Qwen2-Audio，官方仓库](https://github.com/QwenLM/Qwen2-Audio) | 开放音频模型和音频+文字推理示例 | 首个固定模型适配器参考 | 官方示例能运行不等于我们的 8GB 显卡能直接运行，也不保证情绪任务好 |

## 产品与部署选择

开源模型路线可参考 Qwen2-Audio 的官方 Transformers 推理，便于记录具体权重版本和推理设置。本轮尚未装好真实推理环境。

商业服务也有现成音频输入能力，例如 [Gemini 官方 Audio understanding 文档](https://ai.google.dev/gemini-api/docs/audio) 明确支持音频输入、文字输出。它可以减少本地显卡限制，但会引入服务费用、版本变化和数据上传；不是装了 GitHub 插件就自动获得这些 API 权限。第一轮先尝试本地模型，小样本实测后再决定是否需要商业服务。本轮未调用任何商业音频 API。

不追求“最新最大”的模型清单。更重要的是：能否接收实际音频、版本能否固定、参数是否可记录、对照是否公平，以及一次完整实验的成本。第三方量化模型和演示项目可作工程线索，但须单独验证来源和兼容性，不能据其宣传保证能在游戏本上跑。

## 最值得验证的差异化假设

1. 对同一配对同时测试词义和情绪，比单一情绪准确率更容易区分“听不到”和“不该依赖却依赖”。
2. 存在单因素通过、组合因素失败的有效案例；四格检查能够识别它们。
3. 在相同总调用预算下，关系引导的搜索能找到更多不重复且可重现的有效反例。
4. 缩减反例能帮助诊断失败需要哪些因素，而不只是给一个总失败率。

以上都是待验证假设。第一轮只检查前两项的方法可行性。若只有普通情绪识别错误，没有任务切换或交互现象，就应调整研究主张，而不是扩大措辞。

## 阅读顺序与复用边界

先看 CREMA-D 的数据和文件名说明，再看 Qwen2-Audio 的输入示例；随后读 LISTEN/DEAF 的实验对照，最后读 AudioTrust/MTAM 确认安全方向的重叠。AudioBench 可作为工程结构参考。

复用时记录论文版本、仓库 commit、数据许可、下载来源与修改。公开可访问不等于所有数据都能任意再分发；我们优先保存下载/筛选清单而不是把第三方音频打包进 AuRel。这里没有下载或复制任何外部项目源码。
