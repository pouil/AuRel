更新：2026-10-22。用户已明确选择：**优先最小化验证方法；先用公开数据，不自行录音。** 本文把这一选择作为当前路线，后续安全红队与博弈研究保留，但不挤入第一轮验证。

## 2. 下一阶段只回答一个问题

**在同一人、同一句话的两种情绪录音上，模型能否保持词义答案稳定、同时正确改变情绪答案？加入轻度噪声后，这种区别是否仍成立？**

第一轮目标是验证这套方法能够执行、判断可信，而不是一定找到漏洞，更不是达到一个预定攻击成功率。零个确认失败也应报告，不能因此改标签或只挑模型答错的录音。

第一轮固定为：一个公开数据集、一种语言、一个模型、两类任务、一种干扰、固定参数。暂不训练模型，不做付费批量调用，不做大范围搜索，不把博弈求解结果作为研究贡献。

## 3. 公开数据的具体方案

候选：[CREMA-D 官方仓库](https://github.com/CheyneyComputerScience/CREMA-D)。它包含同一批台词的多种情绪表演，还提供只听声音的人工判断，可据此构造配对。它是英文、表演型语料；第一轮结果只能解释这个小范围，不能外推日常对话或中文。

### 目标规模（尚未抽样，不保证全部满足筛选）

- 8 位说话人 × 4 句台词 × 2 种情绪（neutral / happy）= 64 条原始录音，即 32 对。
- 每对必须来自同一人、同一句话。替换情绪录音是配对干预，并非证明只有情绪一个因素改变。
- 使用数据集的 audio-only 人工票数筛选：预定目标标签票比例至少 0.60，且无并列最高票；保留票数和未通过原因。0.60 是本项目试验阈值，不是通用科学标准。先检查元数据结构与票数来源。
- 用音频实际校验补充过滤：文件可解码、有声音、无明显截断，词义与台词一致。标签不明确的样本记“待定/排除”，不要强行二分类。
- 若不足 32 对，按实际数量报告并说明缺口；在看模型输出之前决定是否调整筛选，不根据攻击效果挑样本。

台词建议选 IEO / IOM / DFA / IWL 四类，具体台词可从官方 README 映射。词义任务使用统一的四选一问题，四个候选分别对应四句台词，不要针对每条录音在问题里泄露答案。情绪任务回答 neutral / happy / other / unclear；other/unclear 也记入结果，不丢弃。

词义任务的选项顺序应由固定种子打乱并存档，同一配对及其噪声版本保持一致。台词类别均衡。增加“没有音频”的对照，以检查模型是否仅靠提示猜答案。真实问题与选项在运行前冻结。

数据集只提供 12 种台词，因此非常适合小试验，但不能据此宣称覆盖了广泛词义理解。文件名的情绪代码也不是绝对真值；优先采用 audio-only 人工判断，而不是视频+音频投票。官方 README 还列出异常文件，数据加载器应检查这些情况。

### 数据获取边界

先获取元数据和选中 WAV，避免整库音视频下载。官方仓库使用 Git LFS，普通 ZIP 中可能只是占位文本，并不是真音频。实现下载器时检查文件头、解码和大小，并记录源版本、来源 URL、许可说明与文件哈希（内容指纹）。数据许可链接保留在清单中；代码许可与数据许可分别处理。

本轮文档没有下载这些音频，也没有声称它们已被验证。用户不需要录制任何新语音。

## 4. 每一对录音的四格实验

| 状态 | 声音 | 词义应怎样 | 情绪应怎样 |
|---|---|---|---|
| A | 中性，干净 | 对应台词 | neutral |
| B | 开心，干净 | 与 A 相同 | happy |
| C | 中性，加噪声 | 与 A 相同 | neutral |
| D | 开心，加噪声 | 与 A 相同 | happy |

每格问两种问题，因此每对有 8 次模型预测。第一轮只用固定 25 dB 信噪比的高斯噪声，随机种子、实际信噪比、是否削波都记录。信噪比越大，通常噪声相对越小；25 dB 不保证每条语音的人都听得清，仍需审核。高斯噪声先验证方法，不能代表所有真实背景声。

若 A、B、C 均满足各自任务的预定关系，D 失败，且音频有效、复测可重现，才算该任务的交互失败候选。要逐任务判定，不能把 A 的词义通过与 B 的情绪通过混在一起。

所有失败先经过：音频有效性 → 输出解析 → 标签核对 → 重复运行。清晰度下降导致答案本来就不可判断的，记无效输入；不能算模型漏洞。

## 5. 模型、算力与预算

首个候选为 `Qwen/Qwen2-Audio-7B-Instruct`。官方有音频+文字输入示例。模型不是因“最新”而选，而是有可参考的开放推理实现；具体 revision、processor、依赖版本、精度、生成参数必须冻结。

本机 RTX 4060 Laptop 约 8GB 显存；当前已检测的 Python 使用 CPU 版 PyTorch。下一步先在独立环境做一条短音频的内存和速度测量，再决定量化/CPU offload 是否可行；不承诺这台机器能顺畅运行。量化可能改变行为，结果必须注明配置。若本机不可行，提交远端 GPU 或商业 API 的具体成本估计后再由用户选，不自动租用或付费。

粗略调用预算（未来真实实验，不是当前演示参数）：32 对 × 4 格 × 2 任务 = 256 次；两个预先固定的重复条件共 512 次；无音频对照最多 64 次；接入检查最多 96 次；失败复测额外封顶 128 次。合计上限 800 次模型调用。搜索、人工 judge 或付费 LLM judge 不在第一轮启用。工程上先记录成功、错误、重试的真实账本，不把失败调用藏掉。

4 位说话人用于开发判分规则，另外 4 位用于冻结后的检查；两个组台词相同，因此只检验跨说话人表现，不声称跨台词泛化。样本小，逐人报告和原始分母比单个总百分比更重要。若未来扩大论文实验，再增加独立台词与独立测试集。

## 6. 如何判定第一轮完成

| 检查点 | 交付内容 | 不通过时怎么做 |
|---|---|---|
| 数据真实可用 | 选中样本清单、来源/许可、哈希、标签依据、排除清单 | 修复加载或缩小范围，不进入大批推理 |
| 模型确实听音频 | 一条真实输入的原始输出、配置、耗时、显存记录；无音频对照 | 检查适配器或模型能力，不能用 ToyModel 代替 |
| 每例可追踪 | 256 个预定预测槽位均有成功/失败记录；不静默缺行 | 记录失败原因与预算，再重试 |
| 能区分三种关系 | 按任务输出不变、应变、噪声保持结果及分母 | 修正 oracle/解析，保留原始输出 |
| 判断可信 | 人工检查候选失败和预先随机抽取的通过样本，记录分歧 | 未定项不算确认失败 |
| 可重放 | 固定清单、命令、依赖、模型版本、种子、复测结果 | 先补元数据，不宣布完成 |

最终产物应是一份短报告：测了什么、用了多少数据、哪些关系失效、哪些不确定、能否复现、是否值得扩展。允许结论是“未发现稳定失败”或“当前模型/数据不适合这个问题”。没有要求必须找到若干漏洞。

## 7. 后续可以细化的方向

| 方向 | 增加什么 | 什么时候值得做 |
|---|---|---|
| A：可靠性与交互发现 | 噪声/混响/编码组合、覆盖数组、自动缩减 | 最小试验显示判分有效，可发现稳定候选 |
| B：安全红队 | 有标注的策略任务、良性对照、过拒率、人工安全判分 | 能明确何种输出违反哪条策略；现有情绪结果不能自动升级为安全结果 |
| C：预算搜索 | random 与 UCB/其他搜索等预算比较，独立反例去重 | 已有较大有效输入空间与真实失败信号 |
| D：攻防博弈 | 攻击/防御策略矩阵，良性效用和延迟约束 | 至少有两种有意义的防御；不能靠全部拒绝取胜 |

建议优先 A，然后依据真实发现选择 B 或 C；D 放在最后验证是否增加解释力。仅对固定模型选择扰动是搜索，不是双方博弈。“可复现的有效反例/千次调用”比堆很多攻击名字更能说明贡献。

## 8. 你需要提供什么，哪些由我处理

你不需要提供录音，也不必自己下载全量数据。

| 时间 | 你的操作 | 我的工作 |
|---|---|---|
| 已确定 | 最小方法验证；公开数据优先 | 按这个范围收敛实现 |
| 下一阶段开始 | 若环境安装需要系统交互，完成提示的必要操作 | 编写下载/筛选器、模型适配器、四格评测、日志和报告 |
| 数据校验时 | 用耳机听约 12 对抽样录音，标记“台词是否一致、情绪是否可辨、噪声后是否仍可辨”；不能判断就填 uncertain | 随机化播放顺序、提供审核页面或清单、汇总分歧 |
| 发现候选时 | 与另一位审核者分别复核；如暂时只有你，标明单人审核，不包装成一致意见 | 保留模型原答，按规则分类并复测 |
| 本机不可行时 | 选择继续慢速本地运行或给出远端预算上限 | 先给可核对的成本/时间估计 |
| 进入安全实验前 | 选择策略范围、允许使用的数据和可接受实验成本 | 定义具体 oracle、良性对照与新实验协议 |

初次审核建议预留 20–40 分钟，是工作量估计，不是必须用满的时长。英文听力不够时说明即可，可先利用已有 audio-only 标注并邀请能理解台词的审核者，不要求你猜。人工复核记录模板见 [review-template.zh.md](review-template.zh.md)。

## 9. 技术栈落实顺序

当前：Python + NumPy + unittest + JSON/JSONL + GitHub Actions。下一步按需要加 soundfile/SciPy（读音频、校准噪声）、PyTorch/Transformers（模型推理）、明确的样本清单和输出解析。先不加数据库、网页平台、复杂 agent 或训练框架。

这轮只交付指南与研究计划，不偷偷把付费模型调用或大规模实验当成已经获批的步骤。正式真实语音入口实现后，指南必须增加可执行的命令，再更新“已完成”清单。
